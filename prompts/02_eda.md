# Промпт 2 — EDA с выводами «наблюдение → решение» (раздел отчёта на 4 балла + основа для признаков)

> Запускать после промпта 1 (нужны `io.py`, `splits.py`). Можно параллельно с промптами 3, 4, 6.
> Прочитай `CLAUDE.md`. Работай в `eda/` и `reports/`. Не меняй `src/` (если нашёл баг — опиши в отчёте, не правь).

## Цель
Организаторы оценивают EDA не по графикам, а по **измеримым фактам и связке «наблюдение → принятое решение»** (критерий «EDA и наблюдения по данным», 0–4 балла). Результат: `reports/eda.md` (войдёт в отчёт) + фигуры в `reports/figures/eda_*.png` + таблицы в `eda/tables/*.csv` + один сводный `eda/eda_af.py`, `eda/eda_bs.py`, которые всё пересчитывают (воспроизводимость).

Каждый пункт ниже завершается блоком:
```
**Наблюдение:** … (число, таблица, график)
**Решение для модели/пайплайна:** … (конкретно: признак, фильтр, порог, схема валидации)
```

## Часть A — AF (активное горение)

1. **Дисбаланс.** Доля пикселей огня всего и по чипам; распределение `n_fire_px` (гистограмма, медиана 21, max 243); число компонент связности на чип и их размеры (сколько огня — одиночные пиксели?). → решение по сэмплированию негативов, class weight, порогу.
2. **Сигнал.** Распределения `I4`, `I5`, `I4−I5` для пикселей огня vs не-огня (log-гистограммы, квантили). Доля пикселей огня с `I4 ≥ 367` (насыщение). Сколько «горячих» пикселей (`I4 > 320` / `I4−I5 > 20`) НЕ размечены как огонь — это кандидаты в техноген/блик; где они по landcover и по времени суток. → пороги кандидатов, признаки.
3. **Контекст.** Для каждого пикселя огня и для случайных фоновых — z-score `I4` и `(I4−I5)` относительно окна 5×5, 7×7, 11×11, 15×15 (среднее/std соседей без центра, только valid). ROC-AUC каждого из признаков (одиночный признак vs маска) — таблица. → какие окна брать в признаки.
4. **День/ночь.** По `solar_zenith` (>90 ночь) и по часу `acq_datetime`: доля огня, распределение I4 фона, число «горячих, но не огонь» пикселей. Отдельно: `I3`, `I1`, `I2` для горячих-не-огонь днём (солнечный блик?) → признак блика, правило «ночью I1–I3 не использовать».
5. **Техногенные источники.** Найди повторяющиеся термоаномалии: сгруппируй чипы по тайлу `(epsg, x_min, y_min)`, для каждого пикселя тайла посчитай, в скольких пролётах он «горячий» (`I4−I5 > 15` и `I4 > 310`) и в скольких размечен огнём. Пиксели «горячий в ≥3 пролётах, огонь в 0» — карта техногена. Сколько их, какой landcover (ожидаем 50/60), сколько FP они дадут baseline-порогу. Визуализируй 3–4 примера (чип I4 + маска + landcover). → решение: landcover-признаки, признак «изолированный горячий пиксель на застройке», а также **обсуди в отчёте, почему нельзя переносить эту карту на тест напрямую (правила запрещают восстановление геопривязки), и как модель ловит их по признакам.**
6. **Landcover/метео.** Доля огня по классам landcover; распределение t2m, rh2m, wind для чипов с огнём и без; dem. → какие aux-признаки полезны (AUC).
7. **valid/NaN.** 14 чипов с valid_frac<1: где NaN, есть ли огонь на границе валидности. → обработка NaN в признаках (заполнять фоном, признак «расстояние до невалидного»).
8. **Спутники.** SNPP/NOAA20/NOAA21 — различаются ли распределения I4/I5 фона (калибровка)? → нужна ли нормализация по чипу.
9. **Валидация.** Покажи, что тайлы повторяются (70 тайлов на 420 чипов), сравни оценку случайного KFold и GroupKFold по тайлу для простого правила/бустинга на 3 признаках — числом покажи утечку. → обоснование `configs/folds_af.csv`.

## Часть B — BS (гари и степень поражения)

1. **Классы.** Доля пикселей 0/1/2/3 (глобально и на чип), распределение доли гари на чип, размеры компонент, «дырки» внутри гари. Сколько чипов с cloud_frac>25 %. → веса классов, минимальный размер компоненты в постобработке.
2. **Индексы vs классы.** Посчитай на всех чипах NBR_pre, NBR_post, dNBR, RdNBR, NDVI_pre/post, dNDVI, NDWI, BAI (post), MIRBI, dSWIR (B12_post−B12_pre), яркость видимых. Для каждого — распределение по классам 0/1/2/3 (boxplot/violin, квантили 5/25/50/75/95). AUC «гарь vs фон» и попарная разделимость 1/2, 2/3. → ранжированный список признаков.
3. **Пороги по типу покрова — ключевой пункт.** Для каждого landcover (10, 20, 30, 40, 60, 90…) построй распределение dNBR внутри классов 1/2/3 и подбери оптимальные пороги (максимум mIoU на train) отдельно по покрову. Сравни с USGS (0.1/0.27/0.44 → примерно). Таблица «landcover × класс → медиана dNBR, лучшие пороги, mIoU при глобальных порогах vs по покрову». → доказательство, что baseline с одним порогом плох, и опорные пороги для правил/фичей.
4. **Ложные положительные.** Пиксели с высоким dNBR (> порога слабой степени), но класс 0: где они по landcover (ожидаем пашню 40), какие у них NDVI_pre, dNDVI, яркость B2–B4 post (убранное поле светлеет, гарь темнеет). Примеры 3–4 чипов картинками (RGB pre/post, dNBR, маска). → признаки «яркость post», «NDVI_pre», landcover, и правило для пашни.
5. **Облака/тени/SCL.** Доля пикселей с SCL∈{3,8,9,10} в pre и post; как размечен эталон под облаками (0? класс?); есть ли гарь под «облаком» по SCL (ложный SCL на светлой почве). Разница dNBR под облаком/тенью. → политика: маскировать ли предсказание под облаком, использовать ли SCL как признак, а не как жёсткую маску. Это важно: ТЗ говорит, что облачные чипы из оценки не исключаются.
6. **Sentinel-1.** Распределение VV, VH, dVV, dVH, VH/VV по классам; шум: std в однородных участках до/после медианного фильтра 3×3, 5×5; AUC dVH/dVV «гарь vs фон» отдельно для леса (10) и травы/пашни (30/40). → как использовать SAR (признак после фильтра, вес по покрову) и что сказать в отчёте про верификацию контуров.
7. **Рельеф.** Slope/dem по классам, есть ли связь. → оставить как признак или нет.
8. **Даты.** Разрыв pre→post vs медианный dNBR гари и её площадь (зарастание травы за 2–4 недели): корреляция. Месяц/год. → нельзя использовать даты в тесте, но вывод о фенологии — в отчёт.
9. **Валидация.** Пространственные блоки (`configs/folds_bs.csv`): покажи распределение чипов и классов по фолдам, отсутствие утечки, сравни KFold vs GroupKFold для простого правила dNBR. Временной сплит (2024 как val) — отдельная оценка.

## Часть C — сводка для отчёта
`reports/eda.md`: 1–2 страницы текста + ссылки на фигуры + таблица «Наблюдение → Решение» (не менее 12 строк, по 6 на модуль). Отдельно `reports/eda_key_numbers.md` — 15–20 ключевых чисел для слайдов.

## Технические требования
- Скрипты читают данные через `firemon.io`, кэшируют признаки в `eda/cache/*.npz`, чтобы перезапуск был быстрым.
- Все фигуры с подписями осей, легендами и заголовком на русском; размер шрифта читаемый на слайде.
- Ничего из EDA не должно использовать геопривязку/даты как признак для модели — только для анализа/валидации.
