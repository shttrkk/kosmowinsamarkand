# Промпт 3 — Модуль AF: детекция активного горения и фильтрация техногенных термоаномалий

> Если EDA (промпт 2) уже частично готово — используй `reports/eda.md`; если нет — сделай нужные быстрые проверки сам.

## Цель
Максимизировать **микро-F1 по пикселям огня** на групповой валидации (`configs/folds_af.csv`, GroupKFold по тайлу) и на временном сплите (val = 2024), при инференсе всего 180 тест-чипов за ≤5 секунд на CPU. Выход модуля: `predict_af(chip: dict) -> np.ndarray[uint8] (256,256)` со значениями 0/1.

## Ограничения
- Модель использует ТОЛЬКО содержимое чипа (viirs + aux) и тестовые колонки meta (`valid_frac`). Никаких дат, координат, тайлов.
- Пиксели с `valid == 0` или NaN в I4/I5 → всегда 0 в предсказании.
- Детерминизм: seed 42, `deterministic=True` в LightGBM, фиксированное число потоков.

## План работ (по шагам, каждый шаг — запись в `reports/experiments.md`)

### Шаг 0. Baseline-правило (точка отсчёта)
Контекстный порог по мотивам VNP14: кандидат если `I4 > T_abs` (например 320 днём / 305 ночью) ИЛИ (`I4 − mean_bg(I4) > k·std_bg` И `(I4−I5) − mean_bg(I4−I5) > k·std_bg`), окно 7×7 без центра, только valid. Подбери `T_abs`, `k` на train по F1 (grid). Запиши OOF F1 (для правила OOF = просто train, но честно по фолдам подбирай пороги). Ожидаем F1 ~0.5–0.7. Это «наш baseline», с ним сравнивается всё.

### Шаг 1. Признаки на пиксель (`af_features.py`, функция `compute_af_features(chip) -> (F, 256, 256) float32` + `feature_names`)
Всё векторизовано (numpy/scipy.ndimage), без циклов по пикселям. Использовать `scipy.ndimage.uniform_filter`/`generic_filter` не надо — считать локальные mean/std через uniform_filter по x и x² с нормировкой на маску valid (чтобы NaN не портили окно).
- Сырые: I1, I2, I3, I4, I5, I4−I5, I4/I5, solar_zenith, sensor_zenith, is_night (solar_zenith>90), landcover (как категориальный для LightGBM) + one-hot ключевых классов (50 built-up, 80 water, 40 crop, 60 bare), dem, t2m, rh2m, wind_speed.
- Контекст для окон 5, 7, 11, 15 (по I4 и по I4−I5): фоновое среднее, std, z-score `(x−mean)/(std+eps)`, разность с медианой окна, max соседей, «доля горячих соседей» (`I4−I5>10`). Плюс разность I4 с 90-м перцентилем чипа (нормировка на чип: `I4 − p50_chip`, `I4 − p99_chip`).
- Дневные признаки блика: I3, I3/I2, I1+I2+I3, NDVI из I1/I2 — умножены на `is_day`; ночью 0.
- Морфология кандидатов: число горячих пикселей в компоненте связности (8-связность) по правилу шага 0; расстояние до ближайшего пикселя с landcover 50; расстояние до воды (80); расстояние до невалидного/NaN.
- Все NaN → заполнение медианой чипа + бинарный признак `was_nan`.
Замерь время вычисления признаков на чип (цель < 30 мс).

### Шаг 2. Отбор пикселей для обучения
Всех пикселей 420×65536 ≈ 27.5 млн; огня 9 725. Стратегия: все положительные + все «кандидаты» (правило шага 0 с ослабленными порогами, чтобы recall кандидатов ≥ 99.5 % — измерь!) + случайные 2 % остальных фоновых + все пиксели в радиусе 2 от огня (hard negatives на краях). Итоговый датасет ~1–2 млн строк. Сохраняй в `data/cache/af_train.parquet`.
Важно: на инференсе модель применяется ко ВСЕМ valid-пикселям (либо к кандидатам по тем же ослабленным порогам — тогда recall кандидатов ограничивает сверху F1; выбери и обоснуй).

### Шаг 3. LightGBM (основная модель)
- `objective=binary`, `scale_pos_weight` или `is_unbalance` — сравни; `num_leaves 31–127`, `learning_rate 0.05`, `n_estimators` до 2000 с early stopping по фолдам, `feature_fraction 0.8`, `min_child_samples 50`, `deterministic=True`, `num_threads=8`, `seed=42`.
- 5-fold по `configs/folds_af.csv` → OOF-вероятности на все пиксели → подбор глобального порога по OOF микро-F1 (перебор 0.05…0.95 шаг 0.01). Отдельно проверь пороги для дня и ночи.
- Отчёт: OOF F1/precision/recall; F1 на временном сплите (обучи на ≤2023, проверь на 2024); feature importance (gain) top-25; F1 по срезам: день/ночь, спутник, landcover, размер компоненты (1 px / 2–5 / >5).
- Абляции (каждая — строка в experiments.md): без контекстных признаков; без aux (landcover/метео); без дневных признаков блика; окно только 7; без hard negatives.

### Шаг 4. Постобработка
- Обнулять предсказания на `valid==0`; на `landcover==80` (вода) если днём и I3 высокий (блик) — проверь, помогает ли; удалять изолированные положительные пиксели с низкой вероятностью (порог два уровня: seed p>t_high, рост до p>t_low в 8-связности — hysteresis). Каждая опция — с измерением OOF F1; оставлять только то, что даёт прирост на обоих сплитах (групповом и временном).
- Проверь TTA не нужен (это табличная модель).

### Шаг 5. (Опционально, если GPU свободна и время есть) Небольшая CNN
UNet-lite (или 5-слойная FCN, 32–64 каналов) на входе 8+5 каналов + 4 контекстных признака, loss = focal + dice, 256×256, аугментации: флипы/повороты 90°, батч 16, 40 эпох, AMP, 5 фолдов по тем же фолдам. Сравни OOF F1 с LightGBM; проверь среднее вероятностей (ансамбль). В инференсе допустим только если общее время AF ≤ 10 с на CPU для 180 чипов (проверь на CPU!) — иначе оставить LightGBM. Сохрани веса в `weights/af_*.pt`, экспорт в ONNX приветствуется.

### Шаг 6. Интеграция
- `src/firemon/models/af/predictor.py`: класс `AFPredictor(config)` с `load()` (веса из `weights/af_lgbm_fold{k}.txt` — усреднение 5 фолдов или одна модель на всём train с тем же числом деревьев — сравни и выбери; обоснуй) и `predict(chip) -> mask`.
- `train.py --module af` полностью воспроизводит обучение: признаки → кэш → 5 фолдов → OOF-метрики в консоль и `reports/experiments.md` → финальные веса. Seed фиксирован, повторный запуск даёт ту же OOF F1 ±0.005 (проверь дважды и запиши!).
- `inference.py` использует `AFPredictor`. Замерь время на 180 чипов (можно на `data/test_fake` ×9 или на реальном тесте, когда появится) — цель ≤5 с на CPU, включая чтение файлов. Профилируй (чтение tif, признаки, predict) и оптимизируй узкие места (например, читать tif через rasterio с одним `read()`, LightGBM `predict` батчами по чипу, `num_threads`).
- Тесты `tests/test_af.py`: признаки без NaN и нужной формы; predictor даёт 0/1 нужной формы на чипе с NaN; predictor на чипе без огня даёт мало положительных (<50); детерминизм двух запусков predict.
