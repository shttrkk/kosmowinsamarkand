# Как гнать хакатон через Claude Code (PowerShell) — план на 24 часа

Папка `prompts\` содержит:
- `00_CLAUDE.md` — общий контекст проекта. Копируется в корень репозитория как `CLAUDE.md`; его автоматически читает каждый агент.
- `01_…07_….md` — промпты задач. Каждый — самодостаточный: копируй содержимое целиком в окно Claude Code.
- этот файл — порядок, параллельность, контрольные точки.

## Подготовка (5 минут)
```powershell
mkdir C:\Users\User\hack\fire-monitoring
cd C:\Users\User\hack\fire-monitoring
git init
mkdir prompts; copy C:\Users\User\Downloads\hackatonchik\prompts\* prompts\
copy prompts\00_CLAUDE.md CLAUDE.md
claude
```
В Claude Code первым сообщением: `Прочитай CLAUDE.md, затем выполни задачу из prompts\01_infrastructure.md.` (или просто вставь текст промпта). Разрешить агенту выполнять команды без подтверждения на каждую (`--dangerously-skip-permissions` или режим auto-accept) — иначе 24 часа уйдут на «да/нет».

## Порядок и параллельность

```
[1 Инфраструктура] ── 2–3 ч ── блокирует всё
        │
        ├── [2 EDA]            ┐
        ├── [3 Модуль AF]      │  параллельно, 4 окна PowerShell,
        ├── [4 Модуль BS]      │  каждое — свой git worktree
        └── [6 Сервис]         ┘
                  │
        [5 inference/Docker/скорость/финальный сабмит]   (после 3 и 4)
                  │
        [7 Отчёт + README + презентация]                (после всех)
```

Параллельные агенты в одном репозитории конфликтуют по файлам → **git worktree** на каждую задачу:
```powershell
git worktree add ..\wt-eda -b task/eda
git worktree add ..\wt-af  -b task/af
git worktree add ..\wt-bs  -b task/bs
git worktree add ..\wt-svc -b task/service
```
В каждом worktree свой `claude`. Данные (`data/`) не копировать — в промптах пути относительные; проще всего: сделать `data` символической ссылкой/junction в каждом worktree на общую папку: `New-Item -ItemType Junction -Path ..\wt-af\data -Target C:\Users\User\hack\fire-monitoring\data` (и так же `baseline`, `weights` при необходимости). GPU: задачи 3 и 4 обе могут хотеть GPU — BS (UNet) важнее, AF-CNN опционален; если видеопамяти мало, AF пусть работает на LightGBM.
После завершения задачи: `git checkout main; git merge task/af` (конфликты обычно только в `reports/experiments.md`, README — решать вручную/агентом).

## Контрольные точки (когда возвращаться ко мне в этот чат)
Присылай мне итоговый отчёт агента (`reports/tasklog/NN_*.md` + ключевые числа), я проверяю логику, метрики, ищу ошибки и даю следующий/уточняющий промпт.
- **КТ-1** после задачи 1: время чтения чипа, тесты, GPU определилась, fake-инференс прошёл. + Когда придут baseline и тест — пришли мне список файлов и содержимое baseline-скриптов (RLE, метрика) — сверю с нашими предположениями в CLAUDE.md и, если надо, пришлю правки.
- **КТ-2** через ~2 ч после старта 2/3/4/6: промежуточные OOF (F1_af после правила и после LGBM; IoU_burn/mIoU_sev после правил по покрову и LGBM), проблемы.
- **КТ-3** после 3 и 4: финальные OOF/temporal, времена инференса → я решаю, что идёт в финал, и подправляю промпт 5.
- **КТ-4** первый реальный сабмит на public LB — присылай скор, сравним с OOF (если сильно ниже — ищем утечку/сдвиг).
- **КТ-5** перед задачей 7: все `reports/*.md` — я дам замечания и, если хочешь, соберу презентацию сам здесь.

## Если что-то ломается
- Агент ушёл в бесконечную отладку одного бага > 20 мин → останови, пришли мне лог, я дам точечный промпт.
- Метрика на временном сплите сильно хуже групповой → нормально, это и есть сдвиг «private». Ориентируемся на среднее и не переобучаемся на один сплит.
- Не хватает времени: приоритет по баллам/час: валидный сабмит (без него 0/40) > README+inference+скорость (20) > сервис (12) > отчёт (20, но можно писать из готовых `reports/*.md`) > презентация (8) > лишние эксперименты.
