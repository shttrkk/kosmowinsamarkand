# Промпт 4 — Модуль BS: контур гари и степень поражения (0/1/2/3)

> После промпта 1. Параллельно с 2, 3, 6. Прочитай `CLAUDE.md`. Работай в `src/firemon/features/bs_features.py`, `src/firemon/models/bs/`, `configs/bs_*.yaml`, `train.py` (часть bs), `inference.py` (часть bs), `tests/test_bs.py`, `reports/experiments.md`, `reports/bs_module.md`.
> Это самая весомая часть метрики: `0.35·IoU_burn + 0.30·mIoU_sev` = 65 % Score. GPU доступна — используй.

## Цель
Максимизировать `IoU_burn` (бинарный контур) и `mIoU_sev` (средний IoU классов 1/2/3) на групповой валидации `configs/folds_bs.csv` и на временном сплите (val = 2024). Выход: `predict_bs(chip) -> np.ndarray[uint8] (512,512)` со значениями 0..3. Инференс 89 тест-чипов: цель ≤ 20 с на GPU и ≤ 3 мин на CPU (организаторы могут не иметь GPU — CPU-путь обязателен и должен быть протестирован).

## Ограничения
Только содержимое чипа + тестовые колонки meta (`valid_frac`, `cloud_frac`). Никаких дат/координат. Seed 42, детерминизм (`torch.backends.cudnn.deterministic=True`, `benchmark=False`, LightGBM `deterministic=True`).

## План

### Шаг 0. Baseline-правило
`dNBR = NBR_pre − NBR_post`, пороги USGS (гарь если dNBR>0.10; 1: 0.10–0.27, 2: 0.27–0.44, 3: >0.44) — глобальные. Затем то же с порогами **по landcover** (подбор на train по фолдам). Запиши IoU_burn, mIoU_sev, Score-компоненты для обоих. Это доказательство тезиса ТЗ «один порог заведомо ошибочен» — нужно в отчёт.

### Шаг 1. Признаки (`bs_features.py`, `compute_bs_features(chip) -> (F,512,512) float32`, `feature_names`)
Всё векторизовано. Отражения /10000 → float32.
- Спектральные pre и post: B2..B12 (9 каналов ×2), NBR, NDVI (B8A,B4), NDWI (B3,B8A), NBR2 ((B11−B12)/(B11+B12)), BAI (post), MIRBI, SAVI, яркость (mean B2–B4).
- Разностные: dNBR, RdNBR (= dNBR/sqrt(|NBR_pre|+0.001)), RBR (= dNBR/(NBR_pre+1.001)), dNDVI, dNBR2, dB12, dB8A, dBrightness, dRedEdge (B7−B5).
- SCL: one-hot/флаги для pre и post: cloud (8,9,10), shadow (3), water (6), snow (11), dark (2), nodata (0/1); `scl_bad_any = cloud|shadow` в любой дате; расстояние до ближайшего облачного пикселя (для сглаживания краёв облаков).
- SAR: VV, VH pre/post после медианного фильтра 5×5 (или Lee), dVV, dVH, VH−VV pre/post, d(VH−VV); в дБ (/100).
- Aux: dem (нормированный на чип), slope, landcover категориальный + one-hot (10 деревья, 20 кустарник, 30 трава, 40 пашня, 50 застройка, 60 голая, 80 вода, 90 болото).
- Контекст: средние dNBR/dNDVI в окнах 3, 7, 15; std dNBR 7; для LightGBM — этого достаточно, для CNN контекст даёт сеть.
- Взаимодействие с покровом (для бустинга полезно явно): `dNBR_rel = dNBR / median_dNBR_by_landcover_train` (таблица медиан сохраняется в `weights/`).
- NaN/nodata → 0 + флаг.
Время признаков на чип: цель < 150 мс.

### Шаг 2. Модель A — LightGBM multiclass (быстрая, CPU)
- Отбор пикселей: все пиксели классов 1/2/3 (≈5.9 млн — много; возьми стратифицированную подвыборку до ~1.5 млн) + фон: все в радиусе 5 px от гари (hard negatives, границы) + случайный 3 % остального фона + все пиксели с dNBR>0.1 и классом 0 (ложные кандидаты — пашня). Кэш в `data/cache/bs_train.parquet`.
- `objective=multiclass`, 4 класса, class_weight по обратной частоте (сравни с без весов), `num_leaves 63–255`, `lr 0.05`, early stopping по фолдам, `deterministic=True`.
- 5 фолдов → OOF вероятности (4,512,512) на все чипы. Декодирование: argmax vs **оптимизированные пороги**: сначала бинарное «гарь» по `1−p0 > t_burn` (подбор t по IoU_burn), затем класс = argmax среди 1/2/3 с возможным смещением весов (подбор по mIoU_sev на OOF, координатный спуск по 3 множителям). Запиши оба варианта.
- Абляции: без SAR; без SCL; без landcover; без контекстных признаков; только dNBR+RdNBR+landcover (минимальная модель); regression-вариант (предсказывать порядковую степень 0..3 как число и резать порогами, т.к. классы упорядочены).

### Шаг 3. Модель B — UNet на GPU (основная по качеству)
- `segmentation_models_pytorch.Unet` с encoder `resnet34` (или `efficientnet-b3`, `timm-regnety_016` — сравни 2 варианта, если время) с `encoder_weights="imagenet"` (публичные веса, лицензия — указать в отчёте; первый conv адаптируется на N каналов), `in_channels` = набор ~24–32 каналов: 9 pre + 9 post + dNBR, RdNBR, dNDVI, dNBR2 + SCL-флаги (cloud/shadow pre/post) + VV/VH pre/post фильтрованные + dem_norm, slope + landcover one-hot (5–6 каналов). Нормализация по статистике train (mean/std на канал, сохранить в `weights/bs_norm.json`).
- Loss: CE (веса классов) + Dice (по классам 1..3) — сравни с Focal+Dice; ordinal-вариант (3 бинарных «≥1», «≥2», «≥3» с BCE, декод по порогу) — опционально, если время.
- Обучение: 512×512 целиком (или случайные кропы 256 + полный размер на валидации), batch 8–12, AMP, AdamW lr 3e-4, cosine, 40–60 эпох, early stop по val mIoU_sev+IoU_burn. Аугментации: флипы, повороты 90°, лёгкий шум по яркости (без сильных цветовых — индексы физичны). 5 фолдов по `configs/folds_bs.csv`; лог в `reports/experiments.md`, кривые в `reports/figures/bs_unet_*`.
- Инференс: TTA флипы (4× — измерь прирост и время; если на CPU 89 чипов×4 TTA > 3 мин — отключить TTA в CPU-режиме, конфиг). Half precision на GPU.
- OOF-вероятности → та же процедура декодирования порогов, что и для LGBM.

### Шаг 4. Ансамбль и постобработка
- Среднее вероятностей LGBM и UNet (веса 0.3/0.7, подбор на OOF) → декодирование порогами. Запиши прирост.
- Постобработка (каждый пункт — измерить OOF, оставлять только с приростом на обоих сплитах):
  - вода по SCL (6 в обеих датах) и landcover 80 → 0; застройка 50 → 0 (проверь по GT, что там нет гари);
  - облако/тень по SCL в любой из дат: НЕ обнулять автоматически (ТЗ: облачные чипы в оценке), а сравнить 3 политики: (а) как есть, (б) заполнить предсказание из соседей (морфологическое закрытие/inpaint по ближайшим), (в) обнулить; выбрать лучшую по OOF IoU;
  - удаление компонент < N px (подобрать N, 8-связность), заполнение дыр < M px внутри гари;
  - сглаживание классов внутри гари медианным фильтром 3×3 по меткам (классы соседних степеней перемешаны) — проверить.
- Проверка «классы не пересекаются» встроена (маска 0..3 → три бинарные).

### Шаг 5. Интеграция
- `src/firemon/models/bs/predictor.py`: `BSPredictor(config)` с `load()`/`predict(chip)`, режимы `device: auto|cpu|cuda`, флаг `use_unet`, `use_lgbm`, `tta`. Вес UNet ~100 МБ ×5 фолдов — слишком много: сохраняй **один** финальный чекпойнт (лучший фолд или обученный на всём train с фиксированным числом эпох — сравни на временном сплите) + при необходимости 2–3 фолда; в README — ссылка, как получить веса, и `scripts/download_weights.py`, если они не влезают в git (или Git LFS). Экспорт в ONNX + `onnxruntime` для CPU-скорости — сделай, если даёт ≥2× ускорение.
- `train.py --module bs` воспроизводит всё (признаки → LGBM → UNet → пороги → веса → experiments.md). Повторный запуск: OOF ±0.005 (проверь).
- `inference.py` часть BS: батчами, чтение через `firemon.io`, замер времени отдельно для GPU и CPU режимов — в отчёт.
- Тесты `tests/test_bs.py`: признаки (форма, без NaN), predictor выдаёт 0..3 нужной формы на чипе с облаками и NaN, детерминизм, CPU-режим работает без CUDA (принудительно `device=cpu`).
