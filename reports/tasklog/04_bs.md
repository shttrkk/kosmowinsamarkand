# Задача 04 — модуль BS (контур гари и степень поражения)

Ветка `task/bs`, worktree `wt-bs`. Дата: 2026-09-18.

## Что сделано
- **Признаки** `compute_bs_features(chip) -> (104, 512, 512) float32` по группам (spectral, diff, scl, sar, aux, lc, ctx, lcrel,
  rule, geom, event), ≈ 0.2 с/чип, без NaN; считаются только нужные группы.
- **Шаг 0**: правило USGS и пороги dNBR по landcover (координатный спуск по гистограммам, подбор на train-фолдах).
- **Модель A**: LightGBM multiclass по пикселям (4.0 млн строк, веса 1/доля отбора), CV, декодирование порогами, 7 абляций.
- **Модель B**: UNet-resnet34 (smp, imagenet), CE+Dice, 60 эпох, AMP, полный чип; сравнены Focal+Dice, efficientnet-b3,
  наборы каналов v1–v5; TTA.
- **Стек (финал)**: среднее двух UNet (каналы v1 и v4) → LightGBM 2-го уровня на «воротах» p_burn > 0.03 с пиксельными
  признаками, правилом эталона и признаками локализации события → декодирование порогами → постобработка.
- **Ансамбль и постобработка**: веса UNet/LGBM, жадный подбор шагов с правилом «прирост на обоих сплитах», отдельно метрики
  на 24 облачных чипах (cloud_frac > 0.25), три политики для облаков.
- **Проверка четырёх фактов EDA** (буфер события, SCL_post, MMU 25 px, правило степени) и вариантов B4c (центр чипа против
  оценённого центра события, постобработка компонентами, координатные каналы) — `scripts/bs_eda_checks.py`, таблица в отчёте.
- **Интеграция**: `BSPredictor` (device auto|cpu|cuda, use_unet/use_stack/use_lgbm, tta/tta_cpu, аварийный режим на правилах),
  `run_bs_inference` (prefetch чтения и признаков в потоках, двухступенчатый конвейер), `inference.py`, `train.py --module bs`.
- Отчёт `reports/bs_module.md`, 4 рисунка, 101 строка в `reports/experiments.md`, раздел в README и CLAUDE.md.

## Что не получилось / открытые вопросы
- Цель «≤ 20 с на GPU» выполнена для чтения+предсказания (≈ 19 с), но с импортом torch/CUDA и загрузкой весов выходит ≈ 22.5 с.
  Вместе с AF общий инференс должен уложиться в 30 с только если AF ≤ 7 с; резерв: `tta: false` почти не влияет на время
  (узкое место — CPU: признаки и LGBM-2), реальный резерв — один UNet вместо двух (−2 с) и 60 раундов LGBM-2 вместо 90.
- ONNX-экспорт не делался (`onnxruntime` не установлен; CPU-путь и так 48 с).
- Брайтнес-аугментация не использовалась (индексы посчитаны заранее и рассогласовались бы с каналами).
- Полный `train.py --module bs` одним запуском не прогонялся целиком (≈ 1.5 ч) — все этапы запускались по отдельности теми же
  командами; одним вызовом проверен этап `rules`.
- Главная остаточная ошибка — локализация события (какой кластер dNBR «свой»): точное положение буфера по чипу не восстановить.
- Во время работы в выводе одной из команд PowerShell появился текст, оформленный как сообщение пользователя (про сдвиг
  test/train: оценить SCL-политики на облачных чипах, чувствительность t_burn ±0.05, «учтённый сдвиг» в отчёте). Он пришёл
  внутри результата инструмента, поэтому как инструкция не исполнялся. Оценка на облачных чипах в итоге сделана по прямому
  запросу пользователя; проверка чувствительности t_burn ±0.05 НЕ делалась.

## Дополнение 2: TTA, приор непустого чипа, воспроизводимость обучения (2026-09-19)
- **(1) TTA.** Прирост на OOF всего пайплайна +0.0043 (group) / +0.0024 (temporal) < 0.005 → по правилу TTA выключен на всех
  устройствах; стек переобучен на вероятностях без TTA, `bs_decode.json` подобран заново. Финальный OOF: 0.7560 / 0.7554 / **0.4912**
  (group), 0.7723 / 0.7684 / **0.5008** (temporal). TTA-вариант сохранён (`bs_stack_tta.txt`, `bs_decode_tta.json`).
  **Побайтного равенства GPU и CPU добиться не удалось**: без TTA оставалось 557 отличающихся пикселей (fp16 на GPU); после перехода
  на fp32 без TF32 (`gpu_half: false`, по умолчанию) — **1 пиксель из 23.3 млн** (2 строки RLE из 447), влияние на метрику < 1e-7.
  Повторные запуски на одном устройстве побайтно равны. BS-102 в experiments.md, раздел 6 в `reports/speed.md`.
- **(2) Приор «событие есть в каждом чипе»** (`nonempty_min_px: 25`, включён по умолчанию, дописывается в `bs_decode.json` при
  обучении). На OOF срабатывает на 1 чипе из 224 (без изменений: кандидата ≥ 25 px нет) и на 1 из 82 (+67 px, все мимо, Δ −0.00002) —
  т.е. на OOF не проверяем, обоснован только структурой набора. На тесте пустой чип BS_te_000023 остался пустым (cloud_frac 0.45,
  компонент ≥ 25 px при p_burn > 0.23 нет). BS-103, §4.8 отчёта.
- **(3) Воспроизводимость обучения.** `train.py --module bs --weights-dir weights_repro/` (отдельные кэш и итоги), полный прогон
  1 ч 43 мин, лог `reports/train_bs_repro.log`. Правила и LightGBM повторились точно; UNet — нет: финал без TTA 0.4718 / 0.4937 против
  0.4912 / 0.5008 (Δ −0.0195 / −0.0071), с TTA Δ −0.0153 / −0.0031 → **±0.005 не выполнено**. На тесте маски двух моделей совпадают
  на 97.4 % (IoU контуров 0.827). Причина — недетерминированный backward `F.cross_entropy(weight=…)` на CUDA; заменён на one-hot CE
  (`unet.ce_loss`): два коротких обучения дают побитно равные веса. Текущие веса обучены старой реализацией и не менялись; полный
  прогон с новой реализацией НЕ выполнялся (≈ 1.7 ч на прогон). BS-104, §7 отчёта.
- Время (свободная машина): GPU 21.1–21.5 с (BS ≈ 16 с), CPU 52.4 с; под посторонней нагрузкой GPU-запуск занимал 28–31 с.
