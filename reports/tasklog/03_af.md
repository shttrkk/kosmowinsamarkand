# Задача 03 — модуль AF (ветка `task/af`)

## Что сделано
- **Шаг 0.** Контекстное baseline-правило (`models/af/rules.py::predict_af_context`), пороги день/ночь подобраны grid-поиском
  по фолдам: OOF F1 **0.8965** (temporal 0.9163). Заглушка была 0.2435.
- **Шаг 1.** `features/af_features.py`: 110 признаков, `compute_af_features` (F,H,W) и `af_feature_rows` (n,F) — один код
  расчёта. Время: 25 мс/чип для кандидатов (цель < 30 мс; замер при 100 % загрузке CPU чужими задачами).
- **Шаг 2.** Датасет: огонь + кандидаты + кольцо r=2 + 2 % фона = 649 115 строк, `data/cache/af_train.npz`.
  Recall кандидатов измерен: **100 %** (9 725 / 9 725) при 65 520 кандидатах. Модель обучается и применяется только на
  кандидатах (обучение на всех строках хуже на обоих сплитах).
- **Шаг 3.** LightGBM: OOF F1 **0.9686** (P 0.959 / R 0.978, порог 0.52), temporal **0.9560**. Срезы, top-25 важности,
  5 абляций + варианты гиперпараметров и «день/ночь» — в `reports/experiments.md` (AF-0 … AF-16).
- **Шаг 4.** Гистерезис, удаление одиночных, «вода днём» — ни одна опция не даёт прироста на обоих сплитах → отклонены.
- **Шаг 5.** CNN НЕ делалась: GPU занята задачей BS (5.4 ГБ, 48 %), по условию задачи шаг опционален.
- **Шаг 6.** `AFPredictor`, `train.py --module af`, `inference.py` на `AFPredictor` (откат на правило, если нет весов).
  Среднее 5 фолд-моделей выбрано против одной модели (temporal 0.9559 vs 0.9573 — шум; порог откалиброван на фолд-моделях).

## Как запустить
```powershell
$env:PYTHONIOENCODING='utf-8'
python train.py --module af                       # ~40 с; --no-log, --rebuild-cache
python inference.py --data-dir data/test --output submission.csv
python -m pytest -q tests/test_af.py
```

## Тесты
- `tests/test_af.py` — 10 тестов, все зелёные (синтетический чип день/ночь, NaN, полностью невалидный чип, сверка путей
  расчёта признаков, правило, гистерезис, predictor: 0/1, valid, < 50 px на чипах без огня, детерминизм).
- Полный `pytest -q`: всё зелёное, 2 skip (ждут baseline организаторов), **1 FAILED —
  `tests/test_inference_smoke.py::test_inference_cli_smoke`**. Причина не в коде: в общем (junction) каталоге
  `data/test_fake/af` отсутствуют `viirs/` и `meta.csv` (остался только `aux/`). Так было уже при первом обращении к каталогу,
  до любых моих запусков; мои запуски `make_fake_test.py` писали в scratchpad. Каталог общий для всех worktree и помечен
  «только чтение», другой агент может его сейчас пересобирать — я его НЕ чинил. Эквивалент smoke-теста выполнен на
  приватной копии (180 AF + 2 BS): код выхода 0, валидация submission без ошибок.

## Метрики
| | OOF F1 (GroupKFold) | Temporal 2024 |
|---|---|---|
| заглушка | 0.2435 (весь train) | — |
| правило шага 0 | 0.8965 | 0.9163 |
| LightGBM (финал) | **0.9686** | **0.9560** |

Воспроизводимость: `train.py --module af` из чистого состояния запускался 3 раза (в т.ч. после рефакторинга признаков) —
OOF 0.9686 / temporal 0.9560, md5 всех пяти файлов весов совпадают.
Проверка цепочки на 180 train-чипах через submission: F1 0.999 — это **in-sample** (санитарная проверка RLE и совпадения
признаков, не оценка качества).

Время: AF 180 чипов — 4.96–5.9 с внутри `inference.py` (полный запуск 6.3–7.4 с) **при 100 % загрузке CPU чужими
процессами**. Цель ≤ 5 с — на границе; на свободной машине нужно перемерить.

## Не получилось / открытые вопросы
1. Сломанный общий `data/test_fake/af` — кто-то должен пересоздать (`python scripts/make_fake_test.py`), когда станет ясно,
   что никто им не пользуется.
2. Побочный эффект: `make_fake_test.py --out-dir <scratchpad>` всё равно перезаписал общий
   `baseline/sample_submission_FAKE.csv` (скрипт пишет его безусловно). Содержимое детерминировано (seed 42, весь train),
   но это запись в `baseline/`, которую я не планировал. Стоит добавить в скрипт флаг, отключающий эту запись.
3. Кэш — `npz`, а не `parquet`, как в задаче: в общем `.venv` нет `pyarrow`, ставить пакет в общее окружение не стал.
4. Остаточная ошибка — граница очага (66 % FP в кольце r=2 у огня) и техноген на застройке (F1 0.923): по одному снимку
   без повторяемости дальше не продвинуться. CNN может помочь на границах — не проверено.
5. Время инференса замерено под нагрузкой.
