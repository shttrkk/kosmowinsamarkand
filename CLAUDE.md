## 3. Метрика — точные формулы

Пиксели всех чипов объединяются в общий пул (микро-усреднение):
```
precision = TP/(TP+FP); recall = TP/(TP+FN); F1 = 2PR/(P+R)
IoU(k)   = TP(k)/(TP(k)+FP(k)+FN(k))
F1_af    — F1 по пикселям класса 1 на AF-чипах
IoU_burn — IoU бинарной маски (pred>0 vs gt>0) на BS-чипах
mIoU_sev = (IoU(1)+IoU(2)+IoU(3))/3 по BS-чипам
Score    = 0.35*F1_af + 0.35*IoU_burn + 0.30*mIoU_sev
```
Если знаменатель 0 (класса нет ни в эталоне, ни в предсказании) — величина = 1. Если класс есть в эталоне, но не в предсказании — IoU = 0.
Пиксели эталона с nodata=255: в `src/firemon/metrics.py` есть переключатель `ignore_nodata` (сейчас True — исключаются); default будет выставлен по официальному скрипту метрики после его появления (задача 1b).
Организаторы выдают скрипт метрики вместе с baseline; когда он появится в `baseline/`, наша реализация в `src/firemon/metrics.py` должна давать идентичные числа (тест обязателен).

## 5. Формат submission.csv

UTF-8, разделитель запятая, заголовок `chip_id,class_id,rle`. Ровно строки шаблона `baseline/sample_submission.csv`: по одной на AF-чип (`class_id=1`) и по три на BS-чип (`class_id` 1,2,3), всего 447. Порядок строк произвольный.
RLE: пиксели нумеруются **с 1**, построчно слева направо, сверху вниз (row-major). Строка — пары `start length` через пробел, в двойных кавычках, по возрастанию `start`; серии не пересекаются и **не соприкасаются** (сливать смежные); выход за пределы `H*W` запрещён. Пустая маска → `""` (пустая строка в кавычках), NaN/пропуски запрещены. Внутри BS-чипа маски классов 1/2/3 не пересекаются. Наш кодек `src/firemon/rle.py` должен быть побитово совместим с выданным организаторами скриптом — тест обязателен.

## 6. Предметные факты (использовать в признаках и в отчёте)

**AF.** Очаг 600–1200 K светит в MIR: I4 поднимается на сотни K при доле очага в пиксели <5 %, I5 — на десятки. Признак горения — I4 и разность I4−I5 относительно **фоновой статистики соседей в скользящем окне** (контекстный алгоритм, как в VNP14). Ложные срабатывания: (1) газовые факелы — по одному снимку неотличимы, в эталоне размечены 0 по признаку повторяемости зимой; (2) промышленные площадки/металлургия/ТЭЦ — landcover 50, стабильно тёплые; (3) солнечный блик на воде/крышах/теплицах — только днём, высокий I3 и I1–I2, отношение I4/I5 иное; (4) облака и края сцены. Ночью (solar_zenith>90) фон холоднее, контраст выше, бликов нет.

**BS.** `NBR = (B8A−B12)/(B8A+B12)`, `dNBR = NBR_pre − NBR_post`, `RdNBR = dNBR/sqrt(|NBR_pre|)`. Пороги степени в эталонной разметке **зависят от типа покрова**: для леса/кустарника — шкала USGS, для степи/пашни/поймы — свои, ниже. Значит один глобальный порог заведомо плох, landcover обязан быть признаком. Ложные контуры: убранные/вспаханные поля (положительный dNBR без огня), облака и тени (SCL ненадёжен — светлую почву принимает за облако), дым (давит NIR сильнее SWIR), зарастание травяной гари за 2–4 недели. Sentinel-1: в лесу после пожара падает VH, в степи меняется VV; спекл-шум → медианный фильтр 3×3/5×5 перед использованием.

- Время BS на 89 чипах: GPU ≈ 22.5 с (из них ≈ 3.7 с — импорт torch/CUDA и загрузка весов), CPU без TTA ≈ 48 с.
- В окружении нет `pyarrow`, `onnxruntime`, `psutil` — кэши BS лежат в `data/cache/*.npy` (не parquet).
- В PowerShell-инструменте here-string с двойными кавычками внутри `python -c` ломается — патчи/скрипты писать в файл.
