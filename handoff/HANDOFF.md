### Как пользоваться сборщиком

```powershell
pip install python-pptx markdown          # нужны только для слайдов и PDF, в requirements проекта не входят
python scripts/make_report_figures.py     # графики из чисел: лестница Score, вклад решений, вырезки примеров BS
python presentation/build_deck.py         # → presentation/deck.pptx (печатает, сколько значений не заполнено)
python scripts/export_pdf.py              # → reports/report.pdf, presentation/deck.pdf (нужен LibreOffice)
python scripts/check_placeholders.py      # должно быть «незаполненных плейсхолдеров: 0»
```

В `build_deck.py`: словарь `PENDING` в начале — значения, которые могут измениться (метрики BS, итоговый Score, время, команда);
дальше по одному блоку на слайд (`# 5 ── AF` и т.д.). Помощники: `header` (заголовок), `stat` (крупное число с подписью), `text`,
`table`, `picture(имя_файла_из_reports/figures, x, y, w, h, подпись)` — вписывает картинку в рамку с сохранением пропорций,
`notes` — заметки докладчика. Координаты в дюймах, слайд 13.33 × 7.5. **Если правите pptx руками — сборщик при следующем запуске
затрёт правки**; поэтому либо правьте код, либо после ручной правки сохраняйте под другим именем.

## 4. Десять цифр наизусть

1. **0.31 → 0.83** — Score от двух правил без обучения до полного пайплайна: public **0.3117 → 0.6035 → 0.8267 (TTA) → 0.8262 (v4, детерминизм) → 0.8314 (v5)**; OOF 0.8353, 2024 год 0.8478.
2. **0.968 / 0.960** — F1 огня на групповой и временной валидации; на public ≈ 0.93–0.99.
3. **0.765 / 0.763** — IoU контура гари и средний IoU степени (на 2024 годе 0.790 / 0.783); v4 — 0.756 / 0.755; baseline 0.371 / 0.313.
4. **97 %** — степени в эталоне воспроизводит правило «медианный dNBR 3×3 × тип покрова».
5. **~4 км, 140 px** — радиус буфера события и его смещение от центра чипа; обрезка по центру даёт до −0.17.
6. **0.62 → 0.66 → 0.67** — IoU_burn одной сети v4 на масштабах 1× / 0.75× / 0.5×: больше контекста — лучше выбор «своего» события; v5 против v4: **+0.0053 / +0.0107**, облачные +0.012, public **+0.0052**.
7. **+0.229 и +0.132** — два главных шага: пороги AF относительно фона и обученная попиксельная модель BS.
8. **≈ 23.5 с / ≈ 57 с** — полный инференс v5 на GPU / на CPU на свободной машине (порог высшего балла 30 с, запас ≈ 6 с); быстрый режим v4 — 21 с / 52 с ценой −0.005 Score.
9. **Побайтно один файл** — GPU, CPU и Docker/Linux (у v4 был 1 пиксель из 23.3 млн); формат побайтно совпадает с примером организаторов. **Цена детерминизма на public — 0.0005** (0.8267 → 0.8262).
10. **0.4 с и 0.025 %** — ответ сервиса на весь архив и точность площадей на всех 224 чипах.

Запасные: 0.035 % пикселей — огонь, 41 % очагов — один пиксель; public на 0.004 ниже OOF и на 0.016 ниже 2024 года — переобучения нет; вклад BS на public +0.228 (на OOF +0.273);
повтор v5 с seed 43: +0.0058 / +0.0018 — знак подтверждён; ночная серия — 25 гипотез, принято 2; потолок оракула по компонентам +0.025 / +0.034, классификатор компонент AUC 0.7;
4 UNet одного масштаба −0.0003 / −0.012; `event_zero_r` 300 против 350 — Δ 0.0004, шум; вариант v4 с TTA 0.8344 / 0.8392 / 0.8267; разброс между обучениями UNet до 0.02; облачных чипов в
тесте 25.8 % против 10.7 %; SAR −0.001; застройка F1 0.933; веса 204.8 МБ; слой pred сервиса +0.37 % площади; 163 тестов.

## 6. Открытые вопросы и честные слабые места

1. **Public финала v5 0.8314 против OOF 0.8353 и 2024 года 0.8478**: недобор 0.004–0.016 — ожидаемый (в тесте облачных BS-чипов 25.8 %
   против 10.7 %), переобучения нет. Шаг v4 → v5 на public +0.0052 при +0.0053 на групповой валидации. Если спросят про 0.8262 < 0.8267
   у v4: −0.0005 — сознательная цена детерминизма CPU/GPU.
2. **Финал сменён в последние часы (v4 → v5)** — готовый ответ в `qa.md`, вопросы 26 и 29: правило «+0.005 на обоих сплитах» выполнено
   (+0.0053 / +0.0107), public подтвердил, эффект проверен тремя реализациями. Честная оговорка: повтор с seed 43 дал на временном
   сплите лишь +0.0018 — знак устойчив, величина нет; реалистичное ожидание +0.003…+0.006.
3. **Обучение BS не воспроизводилось** — главный честный пункт. Контрольный полный прогон (1 ч 43 мин): BS-часть v4 0.4912 → 0.4718 (group),
   0.5008 → 0.4937 (2024); разброс до 0.02 при допуске 0.005. Причина — недетерминированный backward взвешенного `F.cross_entropy` на
   CUDA; исправлено one-hot CE, веса побитово равны. **Сети 1× (v1, v4) обучены до исправления, новые сети v5 (0.75×, 0.5×) — после**;
   полный повтор с новой функцией — первый шаг после хакатона (≈ 3.5 ч GPU). Инференс воспроизводим полностью. `qa.md`, вопросы 25 и 29.
4. **Скорость — только на свободной машине**: ≈ 23.5 с (GPU) и ≈ 57 с (CPU), запас до 30 с ≈ 6 с. На загруженной машине организаторов
   порог не гарантирован (v4 под чужой нагрузкой давал 27–28 с вместо 21) — поэтому оставлен быстрый режим `bs.variant: base`
   (21 с / 52 с, −0.005 Score). Готовность к Linux + H100, `Dockerfile.gpu` — см. `reports/tasklog/h100_readiness.md`.
5. **`event_zero_r` 300 против 350**: жадный подбор при переобучении стека даёт 350, Δ 0.0004 — шум; поставляется 300, на нём измерен
   public (`qa.md`, вопрос 30).
6. **TTA выключен сознательно** (−0.0044 / −0.0025 у v4) ради независимости от устройства — вопрос 21.
7. Матрица ошибок, срезы по облачности и абляции BS в отчёте считались на варианте v4 с TTA; для v5 пересчёта нет (порядок величин тот же;
   облачные чипы у v5: 0.699 / 0.691).
8. **Техноген в AF** отделяется только по содержимому чипа: F1 на застройке 0.933 против 0.97. Повторяемость использовать нельзя.
9. **Положение события в BS** — главный нерешённый резерв: оракул по точному региону даёт IoU 0.979 против наших 0.765; оракул по «своим»
   компонентам — +0.025 / +0.034. Классификатор компонент (AUC 0.7) и 4 UNet одного масштаба ничего не дали → положения события в чипе
   нет; в продуктовом контуре его даёт модуль AF (термоточки) — главный пункт плана (слайд 11).
10. **SAR почти ничего не дал** (−0.0008 / −0.0034) — говорить прямо; литература это подтверждает (отчёт, п. 10.1).
11. Слой предсказаний в сервисе — **in-sample**: площадь 237 231.6 га против 236 359.3 га (+0.37 %; у v4 было −1.04 %) — это демонстрация, а не оценка качества.
12. Тег `v1.0-final` ставится релизным коммитом v5 (`reports/tasklog/merge_4.md`).

3. Нарисовать свой **полигон** поперёк гари (инструмент слева) → «Запросить»: контуры обрезаются по полигону, площади
