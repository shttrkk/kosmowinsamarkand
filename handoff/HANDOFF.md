### Как пользоваться сборщиком

```powershell
pip install python-pptx markdown          # нужны только для слайдов и PDF, в requirements проекта не входят
python scripts/make_report_figures.py     # графики из чисел: лестница Score, вклад решений, вырезки примеров BS
python presentation/build_deck.py         # → presentation/deck.pptx (печатает, сколько значений не заполнено)
python scripts/export_pdf.py              # → reports/report.pdf, presentation/deck.pdf (нужен LibreOffice)
python scripts/check_placeholders.py --allow FINAL:SCORE_PUBLIC     # что осталось незаполненным
```

В `build_deck.py`: словарь `PENDING` в начале — значения, которые могут измениться (метрики BS, итоговый Score, время, команда);
дальше по одному блоку на слайд (`# 5 ── AF` и т.д.). Помощники: `header` (заголовок), `stat` (крупное число с подписью), `text`,
`table`, `picture(имя_файла_из_reports/figures, x, y, w, h, подпись)` — вписывает картинку в рамку с сохранением пропорций,
`notes` — заметки докладчика. Координаты в дюймах, слайд 13.33 × 7.5. **Если правите pptx руками — сборщик при следующем запуске
затрёт правки**; поэтому либо правьте код, либо после ручной правки сохраняйте под другим именем.

## 4. Десять цифр наизусть

1. **0.31 → 0.83** — Score от двух правил без обучения до полного пайплайна (OOF 0.8344, 2024 год 0.8392).
2. **0.968 / 0.960** — F1 огня на групповой и временной валидации; на public ≈ 0.93–0.99.
3. **0.763 / 0.761** — IoU контура гари и средний IoU степени (на 2024 годе 0.776 / 0.772); baseline 0.371 / 0.313.
4. **97 %** — степени в эталоне воспроизводит правило «медианный dNBR 3×3 × тип покрова».
5. **~4 км, 140 px** — радиус буфера события и его смещение от центра чипа; обрезка по центру даёт до −0.17.
6. **0.035 % и 41 %** — доля пикселей огня и доля очагов размером в один пиксель.
7. **+0.229 и +0.132** — два главных шага: пороги AF относительно фона и обученная попиксельная модель BS.
8. **20 с / 53 с** — полный инференс на GPU / на CPU (порог высшего балла 30 с).
9. **Δ = 0.000** — два запуска дают побайтно тот же файл; 144 теста.
10. **0.4 с и 0.025 %** — ответ сервиса на весь архив и точность площадей на всех 224 чипах.

Запасные: public 0.3117 → 0.6035 → {{FINAL:SCORE_PUBLIC}}; облачных чипов в тесте 25.8 % против 10.7 %; SAR −0.001; застройка F1 0.933.

## 6. Открытые вопросы и честные слабые места

1. **Public-скор отправки №3 не вписан** (раздел 9). Ожидание: BS-часть на тесте ниже OOF (≈ 0.48 против 0.50) из-за облачности.
2. **Скорость не подтверждена на свободной машине нами**: 20.3–20.8 с (GPU) и 52.7 с (CPU) — замеры автора BS-модуля; контрольный
   замер при слиянии под чужой нагрузкой (CPU 99 %) дал 37–40 с и 96 с. На загруженной машине организаторов порог 30 с не гарантирован.
3. **GPU и CPU дают разные submission** (на CPU нет TTA, fp32): совпадение контуров 0.937. Отправленный файл получен на GPU;
   у организатора без GPU метрика будет немного иной. Требование «±0.005 при повторном запуске» выполняется на одном устройстве.
4. **Docker-образ проверен до подключения BS-модели** (10.8 с, побайтное совпадение). С BS-моделью образ не пересобирался:
   веса 111 МБ войдут в образ, CPU-путь ≈ 53 с. `Dockerfile.gpu` не тестировался вовсе.
5. **`train.py --module bs` одной командой целиком не прогонялся** (≈ 1.5 ч) — этапы запускались по отдельности теми же командами.
6. **Техноген в AF** отделяется только по содержимому чипа: F1 на застройке 0.933 против 0.97. Повторяемость использовать нельзя.
7. **Локализация события в BS** — главный нерешённый резерв: оракул по точному региону даёт IoU 0.979 против наших 0.763.
8. **SAR почти ничего не дал** (−0.0008 / −0.0034) — говорить прямо, не приукрашивать.
9. Слой предсказаний в сервисе — **in-sample** (модели обучены на этих же сценах): площадь 236 654.8 га против 236 359.3 га —
   это демонстрация, а не оценка качества.
10. В ветке `task/bs` идёт небольшая доработка (TTA / приор / воспроизводимость), она будет слита отдельно — после неё числа BS
    могут сдвинуться в третьем знаке; тогда обновить `final_numbers.md` и пересобрать (раздел 9). Тег `v1.0-final` ещё не ставился.

## 8. Демо сервиса на защите

```powershell
cd <репозиторий>
.\.venv\Scripts\Activate.ps1
python -m uvicorn service.app:app --port 8000        # старт ≈ 8 с; дождаться строки «Application startup complete»
```

Открыть http://localhost:8000. Проверка перед выходом: http://localhost:8000/health → `"status":"ok"`.

**Сценарий на 60–90 секунд:**
1. Кнопка **«Демо-запрос»** — bbox `39.25,47.95,39.50,48.10`, период 2024-09-15…2024-10-10. На карте 98 термоточек (красные — день,

3. Нарисовать свой **полигон** поперёк гари (инструмент слева) → «Запросить»: контуры обрезаются по полигону, площади
   пересчитываются — сказать про пересчёт в UTM и точность 0.025 %.
4. Переключатель **«эталон / модель»** — показать слой предсказаний (если собран `firemon.gpkg`, см. ниже).
5. Кнопки выгрузки: **Shapefile** гарей (zip открывается в QGIS) и **CSV** справки.
6. Открыть http://localhost:8000/docs — OpenAPI, сказать «встраивается в региональную ГИС обычным REST».
7. Кнопка «Весь охват» + весь период: 9.7 тыс. термоточек и 43.7 тыс. контуров — ответ за 0.4 с.

**Слой «модель».** После клонирования в репозитории лежит только снимок эталонного слоя. Чтобы работал переключатель
