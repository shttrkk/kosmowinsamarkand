### Как пользоваться сборщиком

```powershell
pip install python-pptx markdown          # нужны только для слайдов и PDF, в requirements проекта не входят
python scripts/make_report_figures.py     # графики из чисел: лестница Score, вклад решений, вырезки примеров BS
python presentation/build_deck.py         # → presentation/deck.pptx (печатает, сколько значений не заполнено)
python scripts/export_pdf.py              # → reports/report.pdf, presentation/deck.pdf (нужен LibreOffice)
python scripts/check_placeholders.py      # должно быть «незаполненных плейсхолдеров: 0»
```

В `build_deck.py`: словарь `PENDING` в начале — значения, которые могут измениться (метрики BS, итоговый Score, время, команда);
дальше по одному блоку на слайд (`# 5 ── AF` и т.д.). Помощники: `header` (заголовок), `stat` (крупное число с подписью), `text`,
`table`, `picture(имя_файла_из_reports/figures, x, y, w, h, подпись)` — вписывает картинку в рамку с сохранением пропорций,
`notes` — заметки докладчика. Координаты в дюймах, слайд 13.33 × 7.5. **Если правите pptx руками — сборщик при следующем запуске
затрёт правки**; поэтому либо правьте код, либо после ручной правки сохраняйте под другим именем.

## 4. Десять цифр наизусть

1. **0.31 → 0.83** — Score от двух правил без обучения до полного пайплайна (OOF **0.8300**, 2024 год **0.8367**).
2. **0.968 / 0.960** — F1 огня на групповой и временной валидации; на public ≈ 0.93–0.99.
3. **0.756 / 0.755** — IoU контура гари и средний IoU степени (на 2024 годе 0.772 / 0.768); baseline 0.371 / 0.313.
4. **97 %** — степени в эталоне воспроизводит правило «медианный dNBR 3×3 × тип покрова».
5. **~4 км, 140 px** — радиус буфера события и его смещение от центра чипа; обрезка по центру даёт до −0.17.
6. **0.035 % и 41 %** — доля пикселей огня и доля очагов размером в один пиксель.
7. **+0.229 и +0.132** — два главных шага: пороги AF относительно фона и обученная попиксельная модель BS.
8. **21 с / 52 с** — полный инференс на GPU / на CPU на свободной машине (порог высшего балла 30 с).
9. **1 пиксель из 23.3 млн** — отличие GPU от CPU; повтор на одном устройстве и Windows против Docker — побайтно. Цена: −0.004 (отказ от TTA).
10. **0.4 с и 0.025 %** — ответ сервиса на весь архив и точность площадей на всех 224 чипах.

Запасные: public 0.3117 → 0.6035 → ожидается (public v4); вариант с TTA 0.8344 / 0.8392; разброс между обучениями UNet до 0.02; облачных чипов в
тесте 25.8 % против 10.7 %; SAR −0.001; застройка F1 0.933; 146 тестов.

## 6. Открытые вопросы и честные слабые места

1. **Public-скор финальной отправки №4 не получен** (раздел 9). Ожидание: BS-часть на тесте ниже OOF (≈ 0.48 против 0.49) из-за облачности.
   Public отправки №3 (вариант с TTA) тоже не вписан.
2. **Обучение BS не воспроизводилось** — главный честный пункт. Контрольный полный прогон (1 ч 43 мин): BS-часть 0.4912 → 0.4718 (group),
   0.5008 → 0.4937 (2024); разброс до 0.02 при допуске 0.005. Причина — недетерминированный backward взвешенного `F.cross_entropy` на
   CUDA; исправлено one-hot CE, на коротком прогоне веса побитово равны. **Финальные веса обучены до исправления**; полный повтор с
   новой функцией не делался (≈ 3.5 ч GPU). Инференс при этом воспроизводим полностью. Готовый ответ — `qa.md`, вопрос 25.
3. **Скорость — только на свободной машине**: 21.1–21.5 с (GPU) и 52.4 с (CPU) — замеры автора BS-модуля. Контрольные прогоны при
   слиянии, когда все ядра были заняты чужим расчётом: 26.8–28.5 с на GPU (первый, с холодным кэшем, — 41 с), 70 с на CPU, 61.5–63.5 с в
   Docker. На загруженной машине организаторов порог 30 с не гарантирован.
4. **TTA выключен сознательно**: −0.0044 OOF / −0.0025 на 2024 годе ради того, чтобы GPU и CPU давали один файл (1 пиксель из 23.3 млн
   вместо 203 тыс.). Если спросят «почему потеряли качество» — вопрос 21 в `qa.md`.
5. Матрица ошибок, срезы по облачности и абляции BS в отчёте считались на варианте с TTA; для финала пересчёта нет (порядок величин тот же).
6. `Dockerfile.gpu` не тестировался. CPU-образ с обеими моделями собран и проверен (файл побайтно равен CPU-прогону).
7. **Техноген в AF** отделяется только по содержимому чипа: F1 на застройке 0.933 против 0.97. Повторяемость использовать нельзя.
8. **Локализация события в BS** — главный нерешённый резерв: оракул по точному региону даёт IoU 0.979 против наших 0.756.
9. **SAR почти ничего не дал** (−0.0008 / −0.0034) — говорить прямо, не приукрашивать.
10. Слой предсказаний в сервисе — **in-sample**: площадь 233 903.7 га против 236 359.3 га (−1.04 %) — это демонстрация, а не оценка качества.
11. Тег `v1.0-final` ещё не ставился.
